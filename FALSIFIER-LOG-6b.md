## What row 6b exposed that the sweep did not

**The published detection rates were not reproducible either.** The README
carried `0.85 / 0.78 / 0.68 / 0.72`. Regenerating from the artifact produces:

| method | README before | artifact now |
|---|---|---|
| LSB | 0.85 | **0.45** |
| DCT | 0.78 | **0.45** |
| GAN_Enc | 0.68 | **0.50** |
| Adaptive_JND | 0.72 | **0.50** |

The current code produces a classifier at or below chance. The published column
did not come from this code, and nothing recorded where it came from. This is
the same defect class as the bit-accuracy column — a published number with no
artifact behind it — and it was invisible until the artifact existed to compare
against.

**This does not establish that 0.45 is correct.** It establishes that the
previous value was unbacked. The detection experiment uses mean channel
intensity as its feature (`np.mean(img, axis=2).ravel()`) for cover versus
stego, which at 1 bpc changes the mean by a very small amount; a value at
chance is consistent with a feature set that cannot see the embedding. Whether
that experiment is correctly specified is a separate question, and it is **not**
answered here. Row 6b required the published value to be derivable. It did not
require the underlying experiment to be sound.

**Recorded as a new finding, not repaired.** It needs its own row and its own
property, on the same footing as finding 2 of DEFECT-004.

## Two errors made during this repair, both recorded

**The reconciler emitted the table twice.** The first implementation appended
the rendered block to an accumulator and then indexed that accumulator with a
*line* number, so the block appeared twice in the file. The consequence was not
cosmetic: with the original table still present elsewhere in the file, the F3
hand-edit detection passed a tampered README, because the comparison found the
untampered copy. A provenance check that tolerates a duplicate of the thing it
is checking does not check anything. The test failing is what surfaced it.

**The first reconciliation dropped the detection column.** The artifact had no
detection block, so every Detect Rate cell rendered as `—` rather than as
something wrong, which would have removed a published column rather than
exposing it. `plot_detection_rate` computed the rates and discarded them, so
`main()` now captures the return value and the artifact carries them.

A third, smaller: the reconciler formatted `bpp` to two decimals, which renders
DCT's 0.0041 as `0.00`. Conditional precision was added.
